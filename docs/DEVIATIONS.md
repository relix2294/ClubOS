# DEVIATIONS — журнал упрощений M0

Формат по ТЗ §0: **что упрощено · почему · когда должно быть исправлено**.
Каждое упрощение — сознательное и ограничено рамками M0 (ТЗ §25).

---

### D-001 · Edge local DB = SQLite WAL (не PostgreSQL)

- **Что:** Edge Controller использует SQLite в WAL-режиме, а не локальный PostgreSQL.
- **Почему:** прямо разрешено ТЗ §7.1 и §25.2.4 для раннего этапа.
- **Когда исправить:** решение SQLite vs local PostgreSQL для production Edge — отдельный ADR (ТЗ §36). Не ранее M2.

### D-002 · Development CA вместо промышленного PKI

- **Что:** индивидуальные device credential выдаёт локальный development CA; ротация описана, но упрощена.
- **Почему:** ТЗ §3.1 явно допускает локальный dev CA на M0 при условии описанной ротации и того, что приватный ключ устройства не попадает в Cloud-логи.
- **Когда исправить:** промышленный mTLS/PKI с отзывом — M1/M2 (ТЗ §27.2).

### D-003 · LockTestMode = полноэкранный overlay, без подмены Shell

- **Что:** `LockTestMode` показывает управляемый полноэкранный тестовый overlay/демо, НЕ меняет Winlogon Shell/GPO/политики.
- **Почему:** ТЗ §3.3 и §25.2.5 прямо запрещают опасную подмену системного Shell на M0.
- **Когда исправить:** настоящий Player Shell — M1 (ТЗ §26).

### D-004 · Минимальная аутентификация

- **Что:** реальная, но минимальная аутентификация сотрудников (не полноценный MFA/refresh-rotation из §8).
- **Почему:** §3.1 требует «минимальную реальную аутентификацию», явно запрещая фиктивную (`admin=true`). Полный AUTH-набор §8 — вне M0.
- **Когда исправить:** MFA, ротация refresh, granular permissions — M1+ (ТЗ §8).

### D-005 · Device Simulator для 5 ПК

- **Что:** 5 «ПК» в панели — симулятор, не реальные Agent.
- **Почему:** §3.4 требует симулятор именно как отдельный, ясно маркированный инструмент; он НЕ заменяет один обязательный реальный Windows Agent.
- **Когда исправить:** не требует исправления — постоянный dev-инструмент; маркировка обязательна.

### D-006 · Boot Node / Player Shell / Remote / POS — только пустые каталоги

- **Что:** каталоги `services/boot-orchestrator`, `services/remote-broker`, `apps/player-shell` присутствуют в структуре, но не реализуются в M0.
- **Почему:** ТЗ §25.4 прямо запрещает реализацию бездиска, remote desktop, реальных платежей и «декоративных страниц» на M0.
- **Когда исправить:** по дорожной карте §26 (M3/M4).
