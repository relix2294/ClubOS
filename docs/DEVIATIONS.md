# DEVIATIONS — журнал упрощений M0

Формат по ТЗ §0: **что упрощено · почему · когда должно быть исправлено**.
Каждое упрощение — сознательное и ограничено рамками M0 (ТЗ §25).

---

### D-001 · Edge local DB = SQLite WAL (не PostgreSQL)

- **Что:** Edge Controller использует SQLite в WAL-режиме, а не локальный PostgreSQL.
- **Почему:** прямо разрешено ТЗ §7.1 и §25.2.4 для раннего этапа.
- **Когда исправить:** решение SQLite vs local PostgreSQL для production Edge — отдельный ADR (ТЗ §36). Не ранее M2.

### D-002 · Development CA вместо промышленного PKI

- **Что:** индивидуальные device credential выдаёт локальный development CA; ротация описана, но упрощена.
- **Почему:** ТЗ §3.1 явно допускает локальный dev CA на M0 при условии описанной ротации и того, что приватный ключ устройства не попадает в Cloud-логи.
- **Когда исправить:** промышленный mTLS/PKI с отзывом — M1/M2 (ТЗ §27.2).

### D-003 · LockTestMode = полноэкранный overlay, без подмены Shell

- **Что:** `LockTestMode` показывает управляемый полноэкранный тестовый overlay/демо, НЕ меняет Winlogon Shell/GPO/политики.
- **Почему:** ТЗ §3.3 и §25.2.5 прямо запрещают опасную подмену системного Shell на M0.
- **Когда исправить:** настоящий Player Shell — M1 (ТЗ §26).

### D-004 · Минимальная аутентификация

- **Что:** реальная, но минимальная аутентификация сотрудников (не полноценный MFA/refresh-rotation из §8).
- **Почему:** §3.1 требует «минимальную реальную аутентификацию», явно запрещая фиктивную (`admin=true`). Полный AUTH-набор §8 — вне M0.
- **Когда исправить:** MFA, ротация refresh, granular permissions — M1+ (ТЗ §8).

### D-005 · Device Simulator для 5 ПК

- **Что:** 5 «ПК» в панели — симулятор, не реальные Agent.
- **Почему:** §3.4 требует симулятор именно как отдельный, ясно маркированный инструмент; он НЕ заменяет один обязательный реальный Windows Agent.
- **Когда исправить:** не требует исправления — постоянный dev-инструмент; маркировка обязательна.

### D-006 · Boot Node / Player Shell / Remote / POS — только пустые каталоги

- **Что:** каталоги `services/boot-orchestrator`, `services/remote-broker`, `apps/player-shell` присутствуют в структуре, но не реализуются в M0.
- **Почему:** ТЗ §25.4 прямо запрещает реализацию бездиска, remote desktop, реальных платежей и «декоративных страниц» на M0.
- **Когда исправить:** по дорожной карте §26 (M3/M4).

### D-007 · Хэш паролей PBKDF2-HMAC-SHA256 вместо Argon2id

- **Что:** пароли хэшируются PBKDF2-HMAC-SHA256 (210k итераций, встроено в BCL), а не Argon2id.
- **Почему:** §27.2 предпочитает Argon2id, но M0 избегает внешних зависимостей; PBKDF2 — современный приемлемый эквивалент.
- **Когда исправить:** перейти на Argon2id (напр. `Isopoh.Cryptography.Argon2`) — M1 (ТЗ §27.2).

### D-008 · Refresh-токен без серверного отзыва

- **Что:** refresh-токен — самостоятельный JWT (typ=refresh) с TTL, без хранения/отзыва в БД.
- **Почему:** §3.1 требует «минимальную реальную» аутентификацию; ротация/отзыв — часть полного §8.
- **Когда исправить:** хранимые refresh-токены с ротацией и отзывом — M1+ (ТЗ §8), связано с D-004.

### D-009 · EF Core миграции без ModelSnapshot

- **Что:** начальная миграция написана вручную; `ClubOsDbContextModelSnapshot` не генерируется (нет .NET 10 SDK локально, B1).
- **Почему:** применение миграций на старте (`Database.Migrate()`) снапшот не требует; он нужен только для `dotnet ef migrations add`.
- **Когда исправить:** сгенерировать снапшот на машине с .NET 10 SDK перед добавлением следующей миграции.

### D-010 · Edge → Cloud sync по HTTP, а не gRPC/WebSocket

- **Что:** Edge отправляет события в Cloud батчами по HTTPS (`POST /api/v1/sync/events`), без gRPC/WebSocket.
- **Почему:** M0 переиспользует уже готовый HTTP-эндпоинт Cloud; соединение исходящее, идемпотентность по `eventId` сохранена (ТЗ §4). Транспорт §25.2.4 назван как ориентир, не жёсткое требование M0.
- **Когда исправить:** постоянный двунаправленный канал (gRPC/WebSocket) — M1/M2.

### D-011 · Схема Edge SQLite через EnsureCreated (без миграций)

- **Что:** локальная БД Edge создаётся `Database.EnsureCreated()`, миграции EF не ведутся.
- **Почему:** Edge SQLite — dev-БД одного узла (D-001); миграции избыточны на M0 и требуют .NET 10 SDK (B1).
- **Когда исправить:** ввести миграции Edge при первом несовместимом изменении схемы — не ранее M1.

### D-012 · Session-host запускается отдельно (без CreateProcessAsUser)

- **Что:** UI (overlay/сообщения) показывает процесс `--session-host` в интерактивной сессии; служба (session 0) не запускает его сама через `CreateProcessAsUser`.
- **Почему:** M0 избегает сложного Win32-интеропа запуска процесса в пользовательской сессии; для ручного теста session-host стартует вручную/через автозапуск (см. runbook).
- **Когда исправить:** автоматический запуск session-host из службы (WTS/CreateProcessAsUser) — M1.

### D-013 · Доставка команд Cloud → Edge через HTTP-эндпоинт приёма

- **Что:** команды доходят до Edge через `POST /api/edge/commands` (идемпотентный inbox), без постоянного канала pull/push из Cloud.
- **Почему:** согласуется с D-010 (HTTP-транспорт M0); Agent забирает команды у Edge локально.
- **Когда исправить:** двунаправленный канал Cloud↔Edge с доставкой команд — M1/M2.

### D-014 · Admin Web на Tailwind без shadcn/ui

- **Что:** UI построен на Tailwind v4 без библиотеки компонентов shadcn/ui.
- **Почему:** M0-набору экранов достаточно нативных элементов + Tailwind; это уменьшает зависимости и генераторы. ТЗ §7 называет «Tailwind/shadcn» как ориентир стека.
- **Когда исправить:** ввести shadcn/ui при росте числа компонентов — по мере надобности (M1+).

### D-015 · NuGet-audit (NU19xx) не блокирует сборку

- **Что:** предупреждения аудита NuGet о транзитивных уязвимостях (`Microsoft.OpenApi` 2.0.0, `SSH.NET`, `SQLitePCLRaw` — через AspNetCore.OpenApi/Testcontainers/EF Sqlite) выведены из `TreatWarningsAsErrors` (`WarningsNotAsErrors=NU1901..NU1904`). Аудит остаётся включён и виден в логах.
- **Почему:** это транзитивные зависимости апстрим-пакетов; корректно чинятся апгрейдом апстрима, а не жёстким pin'ом в M0. Компиляторные предупреждения по-прежнему = ошибки.
- **Когда исправить:** поднять версии, когда апстрим (Microsoft.AspNetCore.OpenApi, Testcontainers) выпустит обновления с починенными транзитивами — M1; тогда вернуть NU19xx в ошибки.
